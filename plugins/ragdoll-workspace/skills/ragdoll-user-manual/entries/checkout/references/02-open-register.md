## 適用情境

未開帳（`reportStatus !== 'OPENED'`）時，商品明細區會顯示遮罩「目前為關帳狀態，
如需結帳請先完成開帳動作」，所有結帳操作（掃描、變更數量、移除、變價、小計）
都會被 `guardCheckout()` 攔下。必須先完成開帳才能繼續。

## 操作步驟

有兩種進入開帳對話框（`OpeningEntryDialog`）的方式：

1. **遮罩內按鈕**：商品明細區遮罩內的「立即開帳」按鈕（實機截圖已確認畫面上
   存在此文字與按鈕）。
2. **功能選單**：點擊頂欄「功能選單」（`data-testid="pos-menu-btn"`，未登入
   銷售員時 disabled）→ 商品分頁「開帳」（`data-testid="menu-opening-btn"`）。
   若目前狀態是 `REOPEN`（跨日未關帳），此按鈕會改為導向「請先清帳後再開帳」
   並直接開啟關帳對話框，不會進入開帳流程。

開啟開帳對話框後：

1. 輸入「開櫃櫃金」（`id="tillMoney"`，數字，不可為負數，為空視為 0）。
2. 輸入「前日留存」（`id="retentionMoney"`，數字，預設 0）。
3. 可選：對話框下方會顯示「最近開帳紀錄」表格（帳務日 / 開櫃櫃金 / 前日留存），
   點擊任一列可直接帶入該筆金額到上方輸入框。首次開啟時若欄位為空，會自動帶入
   最近一筆歷史紀錄的開櫃櫃金。
4. 點擊「確認開帳」按鈕（無 `data-testid`，以按鈕文字定位）。

## 系統驗證行為

- 確認開帳前，系統會先呼叫 `checkStuckRemoteReport` 偵測中台是否卡著一張跨日
  未關閉的舊日結單。偵測到時彈出巢狀確認對話框「偵測到跨日未關閉的日結單」，
  需操作員確認後才會以其員編呼叫關閉舊帳，成功才繼續走開帳流程。
- 開櫃櫃金為負數時，toast「開櫃櫃金不能為負數」，不會送出。
- 開帳成功後，Dialog 直接關閉作為完成回饋（**不會**額外跳 toast）。
- 開帳成功後，功能選單的「開帳」按鈕會顯示「已開帳」Badge，且該按鈕文字/用途
  轉為「修改當班金額」——已開帳時再開此對話框，改的是同一張日結單而非新開一張，
  且不再偵測卡帳。

## 注意事項

- ⚠️ 待確認：「立即開帳」遮罩按鈕與「功能選單 → 開帳」是否開啟的是完全相同的

  需人工在實機環境進一步確認。
