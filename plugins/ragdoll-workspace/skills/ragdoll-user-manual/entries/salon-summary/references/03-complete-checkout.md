# 美容完成結帳、進度彈窗與失敗處理

> 來源：原始碼（`next/app/salon-summary/components/salon-checkout-button.tsx`、
> `next/app/summary/components/checkout-processing/index.tsx`）+ E2E Page Object
> （`test/e2e/pages/salon-summary-page.ts`）與 `test/e2e/9-salon/salon-payment-complete.spec.ts`。
> ⚠️ 本檔的美容結帳流程（步驟順序、攔截順序、失敗處理）**僅依原始碼撰寫，未經 runtime 驗證**：
> 完成結帳會建立 dev 美容銷售單並可能請款／出紙，本次未執行。進度彈窗與完成畫面是與商品側
> **同一個元件**，其畫面樣式已在 `entries/summary/references/05-…` runtime 驗證。

## 適用情境

美容付款頁已選好付款方式且足額，按「完成結帳」（`data-testid="salon-checkout-btn"`）落地美容服務
銷售單、開錢櫃、列印發票與小白單。

## 點擊後、彈窗出現前的攔截（紅色 toast，不建立銷售紀錄，按鈕維持可重按）

依序（**與商品側順序不同**：先檢查付款是否足額，再檢查載具漏印）：

| 順序 | 提示 | 情境 |
|------|------|------|
| 1 | 該欄位的格式錯誤說明（無則「請確認發票資訊」） | 載具／統編／捐贈碼有格式錯誤（留空不擋） |
| 2 | 請先選擇付款方式並完成付款 | 沒有選付款方式，或金額不足 |
| 3 | 已選擇「手機載具」，請記得輸入發票資訊（捐贈為「捐贈碼」） | 選了載具／捐贈且應付（扣除宜睿與消費券後）> 0，但號碼留空 |
| 4 | 顯示對應原因 | **非帶入單**才會做：折扣碼、會員優惠券、點數禮物卡、包月混單的即時重驗（付款期間折扣碼可能已過期或被同店另一台用掉） |

帶入既有未付款單（鎖定匯入單）**一律跳過第 4 項重驗**，因為確認結帳當下已驗證過。

**付款內容在點擊當下就定格**：付款方式、宜睿、One 碼三者在按下按鈕的瞬間快照，之後即使有人返回或清空
付款，本次送出的這一筆仍沿用快照內容，確保已開立發票的服務單一定帶著實際收款方式。

## 進度彈窗（同商品側元件）

處理中：「處理中...」＋（現金付款且建單成功後）「找零金額 $N」＋五個步驟。按鈕顯示「處理中...」並停用；
同步重入防護避免快速雙擊落地兩張服務單、耗用兩個發票號碼。

| 步驟 | id | 內容與失敗處理 |
|------|----|----------------|
| 建立銷售紀錄 | `create-sale` | **唯一硬失敗點**。沿用確認結帳時預先產生的服務銷售單編號（有點數折抵預扣時），否則自行產生。失敗（回報不成功）：步驟標錯誤（原因或「結帳失敗」）、完成畫面標題「結帳未完成」；**刻意不歸還點數折抵預扣**（收銀員可能直接重試，重試沿用同一筆預扣）。拋例外：紅色 toast 顯示訊息，彈窗不出現，按鈕恢復可重按 |
| 開啟錢櫃 | `open-drawer` | 不論付款方式一律開；失敗標「開啟錢櫃失敗，請手動開啟」 |
| 列印發票 | `print-invoice` | **不會**先探測發票機；失敗標錯誤「{訊息}，請於銷售列表補印」（單已落地可事後補印） |
| 列印小白單 | `print-coupon` | 先探測發票機：離線標灰字「發票機目前無回應，已略過小白單列印」（測試門市字樣略異）；無可印小白單標灰字「本筆無需列印的小白單」；攤算服務異常時標錯誤「攤算服務異常，活動小白單未列印；一般小白單已印出 N 張」（或「…本筆無需列印的一般小白單」），**只印出一般券**；其餘失敗標「{訊息}，小白單列印失敗」。員購與共用會員的短路在函式內處理 |
| 清除購物車 | `clear-cart` | 清空美容主 store、美容折扣碼、付款、宜睿、One 碼、發票、**已綁定的會員**（避免點數／優惠券跨客戶外溢）。失敗標「{訊息}，請重新整理頁面」，仍走向完成彈窗，按鈕維持停用以防對同一批購物車重複送出 |

### 帶入未付款單時建立銷售紀錄拋例外

本地不一定真的沒寫入（例如 IPC 回應遺失）。系統先查本地是否已存在指向同一張未付款單的美容銷售紀錄：
**已存在**→ 步驟標錯誤「此筆結帳可能已成功送出，請至銷售查詢確認結果，勿重複點擊」＋同名 toast，
完成畫面標題「結帳未完成」，不放行重試（避免中台端「非未付款拒絕覆寫」衝突）；**不存在**→ 一般錯誤 toast，
可重試。

## 完成畫面

- 標題三態同商品側：「交易完成」「交易完成（部分錯誤）」「結帳未完成」。現金付款顯示「找零金額 $N」
  （0 時「現金付款，無需找零」），非現金不顯示找零。
- 「返回購物車」（`checkout-confirm-btn`）：觸發背景上傳離線銷售單並導向 `/checkout`。
  E2E 的 `waitForCheckoutComplete` 就是等此按鈕出現、點擊、再等 URL 變回 `/checkout`。
- 與商品側的差異：完成後**依原始碼不登出銷售員**（只清會員）；購物車已在「清除購物車」步驟清空，
  按「返回購物車」時不再重複清空。

## 與資料層的對應（供驗收對照）

- 落地的是 `offline_sale`（`saleKind = SERVICE`），上傳狀態一開始為待上傳（`PENDING`），背景上傳
  在按「返回購物車」後觸發；帶入未付款單完成時 `originalSaleName` 等於被帶入的單號
  （見 E2E `salon-payment-complete.spec.ts`）。
