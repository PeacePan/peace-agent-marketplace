# 進入付款頁與畫面核對（商品模式）

> 來源：原始碼（`next/app/checkout/page.tsx` 的 `handlePromotionSummaryConfirm`、
> `next/app/summary/page.tsx`、`components/discounts-total-block/`、
> `components/product-details-block/`、`components/connection-status.tsx`）+ E2E Page Object
> （`test/e2e/pages/summary-page.ts` 的 `waitForReady`）。
> runtime（2026-09-30，dev v1.2.0）已驗證：小計→加購與贈品→促銷結算→確認結帳→付款頁的流程與
> 畫面版面、購買明細與折扣區內容、空車時不顯示付款摘要。下方「守門」表格各列為僅依原始碼撰寫

## 適用情境

商品模式購物車已加入商品、已開帳、已登入銷售員，要從結帳頁進入付款頁。
促銷結算對話框本身的操作（優惠券、折扣碼、點數折抵等）本次手冊列為待補，
此處只記錄「按下『確認結帳』之後」為什麼能／不能進入付款頁。

## 操作步驟

1. 在 `/checkout` 點「小計」（需已開帳、已登入銷售員，且「檢查數量」欄位填入與購物車相符的件數）。
   依序出現：
   - 「加購與贈品」彈窗（分頁：加購區／贈品區／點加金；無活動時顯示「目前沒有可用的加購活動」），
     底部「略過」或「確認選擇」；
   - 「本銷售適用促銷結算」對話框：左側「商品與促銷」（無促銷時顯示「此筆銷售單無適用的促銷活動」
     ＋「其他商品（無促銷）」分組）、右側「優惠與折抵」（會員優惠券、會員點數、折扣碼、整單折扣；
     未登入會員時顯示「尚未登入會員」）、底部結算列（商品小計、商品促銷、優惠券、整單折扣、折扣碼、
     點數折抵、應付金額）。
2. 點對話框底部「確認結帳」（`data-testid="promotion-summary-confirm-btn"`）。
   處理中按鈕會顯示 loading 並 disabled，期間不可重複點擊。
3. 全部守門通過後畫面導向 `/summary`，對話框隨之關閉；二顯同時切換為付款中畫面
   （見 `entries/customer-display/references/02-payment-and-completed.md`）。
4. 付款頁載入完成的判斷：右下角「完成結帳」按鈕（`checkout-btn`）出現。

## 進入付款頁前的守門（依序，任一項失敗對話框保持開啟、不會導頁）

| 順序 | 情境 | 畫面提示（toast） |
|------|------|------------------|
| 1 | 發票欄位有格式錯誤（載具／統編／捐贈碼；欄位留空**不**擋） | 顯示該欄位的格式錯誤說明 |
| 2 | 發票機探測斷線，且本店不是測試門市 | 紅色「發票機目前無回應，請確認發票機是否正常運作」，不放行 |
| 2 | 發票機探測斷線，但本店是測試門市 | 黃色「發票機目前無回應」，放行 |
| 3 | 折扣重新計算失敗 | 顯示實際失敗原因，不放行（避免帶著全 0 金額進入付款頁） |
| 4 | 本機台發票配號用盡（0 元交易、專櫃門市、非電子發票帳務別不檢查） | 「該機台可用發票號碼已用盡，請聯繫財務調整配號區間」 |
| 5 | 外送匯入單為「寵速配」且結算總計與平台訂單金額不符 | 「結算總計 $X 與外送平台訂單金額 $Y 不一致，無法進入付款，請重新確認購物車商品數量與金額」 |
| 5 | 外送匯入單（寵速配／UberEats／FoodPanda／Foodomo）購物車沒有任何購物袋料件 | 「寵速配、UberEats、FoodPanda、Foodomo 訂單需至少有一筆購物袋料件」 |
| 6 | 有套用會員點數折抵，但活動設定已失效 | 「會員點數折抵活動設定已失效，請先移除點數折抵後再試」 |
| 6 | 點數折抵即時核銷失敗且目前離線／網路層失敗 | 「目前無網路連線，含點數折抵的結帳無法完成，請先移除點數折抵或稍後再試」 |
| 6 | 點數折抵即時核銷失敗（如點數不足） | 顯示後端回傳的訊息；無訊息時為「核銷點數折抵失敗，請稍後再試」 |
| — | 其他例外 | 顯示實際錯誤訊息；無訊息時為「結帳前檢查失敗，請稍後再試」 |

會員點數折抵是「確認結帳當下」就即時核銷（預扣），不是等到完成結帳；因此在付款頁按「返回」
會把這筆預扣歸還（見 `05-…` 的「返回」段）。

## 進入後應核對的畫面內容

1. **子標題**為「付款確認」；資訊列的「通路」欄顯示本筆通路（一般門市銷售為「門市銷售」；
   外送匯入單為對應平台）。
2. **購買明細**逐項列出料件編號【條碼】＋品名、單價 × 數量、小計；有套用商品促銷的品項下方
   接一條促銷標籤（名稱＋紅字 `-$金額`）。加購、贈品（價位欄顯示「贈品」）、點＋金商品
   （價位欄顯示「N 點 + $金額」）各自有分組標題。
3. **折扣與應付**區：折扣金額大於 0 才以紅字顯示 `-$`，否則顯示 `$0`；「應付金額」＝商品小計
   扣除各類折扣；**宜睿票券折抵不在此區扣除**，只出現在右下角付款摘要。
   「共 N 件商品」是購物車所有品項（含贈品、加購）的數量加總。
4. **換購**：出現「原訂單抵扣 (原銷售單號)」負向金額；原單金額大於新單應付時多一列綠色
   「換購找零」，小於時多一列琥珀色「換購差額」，相等不顯示。
5. **右下角付款摘要清單**在尚未選任何付款方式時不顯示（整塊不渲染），選了之後才出現。
6. 離線時右側出現離線提示（見 `AGENT.md`）；離線不影響付款按鈕本身，但信用卡、One 碼、
   宜睿票券依賴外部服務／設備，離線時能否使用以各自畫面回應為準。

## 空車與重新整理

- 直接在付款頁按重新整理，或由首頁「訂單查詢」進入：購物車為空，頁面立即 `replace` 回
  `/checkout`，不會停留。
- 結帳流程進行中（進度彈窗開啟到按下「返回購物車」之前）不會觸發這個導回。

## 注意事項

- 付款頁的資訊列只用來核對本機主檔新舊（門市、機台、資料同步時間），不提供手動同步；
  需要同步請回 `/checkout`。
- 進入付款頁時前一頁殘留的 toast 會被清掉；E2E 的 `waitForReady` 也會主動關閉初始化 toast，
  否則後續操作可能被 toast 遮住而等待其自動消失。
