## One 碼（`taishin-pay-btn`，主付款，全額）

### 操作步驟

1. 點「One 碼」→ 通過守門後對話框「One 碼付款」（`taishin-pay-dialog`）開啟，說明「請刷入或輸入 One 碼
   序號」，輸入框 `taishin-barcode-input`（placeholder「請輸入序號...」），右側「驗證」
   （`taishin-confirm-btn`）。
2. 刷入或輸入序號。系統會在背景辨識序號前綴；**辨識成功前「驗證」維持停用色**，畫面不顯示支付別名稱
   （TAIWAN_PAY 與 iPASS MONEY 共用前綴，付款前無法確定，待付款結果回來才確定）。
3. 按「驗證」（或 `Enter`）→ 按鈕轉為 loading、輸入框停用。
4. 成功：對話框自動關閉，「One 碼」按鈕顯示 ✓（`taishin-pay-success`），其餘付款按鈕全部停用，
   「返回」被鎖住，摘要列「One 碼」不可移除。
5. 失敗：對話框內出現紅色錯誤（`taishin-error-msg`，附錯誤代碼與回報按鈕），可修改序號再驗證。

### 系統驗證行為

- **對話框一開，右下摘要就會出現「One 碼 $應付」（沒有 ✕）與「尚欠 $應付」**——此時尚未付款，
  只是主付款已被設為 One 碼；按 `Esc` 或點對話框外關閉（非處理中）會重置，摘要列隨之消失（已驗證）。
- （⚠️ 依原始碼）選 One 碼會**取代**已輸入的現金等主付款（主付款單一互斥）；但已有信用卡（指定／離線）、
  消費券時被擋，toast「One 碼不得搭配其他付款方式」；已核銷宜睿時按鈕直接停用。
- 處理中按 `Esc`／點外面不會直接關閉，改跳確認對話框「台新 One 碼付款處理中」：
  「付款正在處理中，此時離開可能導致金額與畫面顯示不同步。確定要離開嗎？」，「取消」保留、
  「確定離開」才真正離開。
- 延遲回應：收銀員離開後才抵達的成功回應，若金額仍等於目前應付，系統補回 One 碼付款並可直接結帳；
  若期間改了購物車導致金額不符，toast「台新 One 碼延遲回應的金額與目前應付金額不符，請勿完成結帳，
  需依交易明細人工核對」。
- 購物車全部品項都沒有料件編號時無法啟動，toast「台新 One 碼付款無法啟動：本次結帳無可送出的料件編號，
  無法完成 One 碼付款」。

## 宜睿票券（`edenred-voucher-btn`，副折抵）

### 操作步驟

1. 點「宜睿票券」→ 通過守門後對話框「宜睿票券核銷」（`edenred-voucher-dialog`）：「請刷入或輸入票券
   序號」，輸入框 `edenred-voucher-input`，「驗證」（`edenred-query-btn`，`Enter` 亦可）。
2. 驗證成功切到票券詳情：「票券驗證成功」＋產品編號、產品名稱、類別、券種、餘額、到期日期；
   「折抵金額」輸入框（`edenred-redeem-amount`）——**單次使用的面額券固定用面額、不可改**，其他券可在
   1 ～ 「餘額與剩餘應付的較小值」之間調整；琥珀色提醒「若此筆訂單尚須支付餘額，則僅可使用信用卡與現金
   結帳，請先與客人確認付款方式喔！」；按鈕「返回」「確認核銷」（`edenred-authorize-btn`）。
3. 「確認核銷」是**不可逆**的即時交易。成功後回到輸入場景（面板**不會**自動關閉），底部顯示
   「已核銷 N 張票券 −$金額」與「餘額應付 $金額」，或（已滿足時）「金額已滿足，可直接結帳」；
   可繼續加下一張，按 `Esc` 關閉面板。
4. 查詢或核銷失敗：面板內顯示紅色錯誤（`edenred-error-msg`）。

### 系統驗證行為

- 核銷後：One 碼停用；PandaGo／外送付款被守門擋下（toast「若使用宜睿票券，餘額僅可透過現金/信用卡結帳」）；
  消費券被擋（toast「消費券不可與宜睿票券搭配使用」）；餘額只能用現金或信用卡（含離線）。
- 已核銷任何一張、或核銷／查詢進行中，「返回」被鎖住；摘要列「宜睿票券」不可移除。
- 宜睿折抵**不會**反映在「應付金額」，只顯示在右下摘要；找零與尚欠都已扣除宜睿。
- 信用卡（全額）已成功時點宜睿，toast「已使用「信用卡(全額)」完成付款，請完成結帳動作」，面板不會開。
- 美容付款頁針對包月／住宿／安親會停用此按鈕，見 `entries/salon-summary/`。

## 消費券（不找零）（`stimulus-voucher-btn`，副付款）

- **只有特定門市會顯示**：種子店家檔命中關鍵字「顯示消費券」的機台才有此按鈕；其餘門市該格**留空**
  （`stimulus-voucher-slot-placeholder`，後方按鈕不會位移）。查詢未完成或失敗時一律不顯示。
  本次 runtime 驗證的門市不在名單內，看到的就是留空格。
- 操作：點按鈕 → 前置檢查通過 → 數字鍵盤（標題「消費券（不找零）」，快捷鍵同現金，7 位數上限）→
  輸入券面**總額** →「確認」。輸入 0 靜默忽略。
- 券面不設未付上限、**不找零**：超過應付的部分顯示在摘要底部「溢收（不找零）」。
- 只能搭配現金／信用卡。提示：「消費券不可與宜睿票券搭配使用」、「此付款方式不可與消費券搭配」
  （主付款為 One 碼／PandaGo／外送）、「已輸入消費券金額，請先移除再重新輸入」、「已付清款項」。
- 摘要列「消費券(不找零)」可用 × 移除後重輸。

## PandaGo（`pandago-btn`，主付款，全額）

1. 點「PandaGo」→ 對話框「PandaGo」（`pandago-dialog`）：「請輸入 PandaGo 訂單編號（6 碼英數字）」，
   輸入框 `pandago-order-no-input`（placeholder「例：abc123」，最多 6 字）。
2. 輸入未滿 6 碼或含非英數字：輸入框下方紅字「PandaGo 訂單編號為 6 碼英數字」
   （`pandago-format-error`），「確認」（`pandago-confirm-btn`）維持停用色。**只驗證格式，不會查詢平台。**
3. 合法後按「確認」（或 `Enter`）→ 對話框關閉，按鈕顯示 ✓，摘要出現「PandaGo $應付」＋ ✕
   （`payment-summary-remove-PANDAGO`）；視為已付清全額，「外送付款方式」按鈕同時停用（已驗證）。
4. 已付清（例如已足額現金）時再選 PandaGo 會被守門擋下並 toast「已付清款項」；已核銷宜睿或已輸入消費券時
   也被擋（toast「若使用宜睿票券，餘額僅可透過現金/信用卡結帳」／「若使用消費券，餘額僅可透過現金/信用卡結帳」）。
   （⚠️ 依原始碼）PandaGo 會取代已輸入的現金；先選 PandaGo 之後再加信用卡（指定／離線）則被擋，
   toast「此付款方式不可與信用卡指定金額搭配」／「…信用卡(離線)指定金額搭配」。

## 外送付款方式（`delivery-payment-trigger`，主付款，全額）

- 點「外送付款方式」展開浮層「選擇外送平台」（`delivery-payment-panel`），2×2 四顆：**UberEats**、
  **Foodomo**、**FoodPanda**、**寵速配**（testid `delivery-payment-uber_eats`／`-foodomo`／
  `-food_panda`／`-fast_buy`）。
- **一般門市通路下四顆全部停用**（已驗證）；只有銷售單通路等於該平台（外送匯入單）時對應那顆可點，
  停用時滑鼠停留的提示為「此付款別限定 {通路} 通路」。已付清時整顆觸發按鈕也停用。
- 選平台後先跑付款守門，通過才開對話框「{平台} 外送訂單編號」（`delivery-order-no-dialog`）：
  平台匯入單的編號**唯讀**（說明「請輸入外送訂單編號（已帶入，請確認一致）」），手動情境則可編輯
  （說明「請輸入外送訂單編號」）；「確認」（`delivery-order-no-confirm-btn`）需編號非空白，
  「取消」（`delivery-order-no-cancel-btn`）只關閉不提交。
- 確認後主付款設為該平台；匯入單若選的平台與訂單平台不同，完成結帳時會被擋
  （見 `05-…`「完成結帳前的攔截」）。
- 外送匯入本身（如何產生非門市通路的銷售單）本次手冊列為待補。
