# 整理函式與類別（26–50）

目的：拆分或整併函式、變數與類別。

這一組很多招式是成對的反向操作（抽取與內聯、隱藏委派與移除中間人、抽取類別與內聯類別、抽取父類別與攤平類別階層）。要用哪個方向，看的是「改完之後讀的人是不是更容易理解」，不是看哪個招式聽起來比較進階。

每則的「圖卡指令」是原圖卡上給 AI 的標準說法；「做法與注意」是補充說明，不是圖卡原文。

---

### 26 抽取函式
- 目的：替一段完整的邏輯命名
- 做法與注意：把有獨立用途的區塊搬成函式，名稱說「做什麼」而不是「怎麼做」。抽出的函式要能一句話說明；抽完引數很多時，先考慮引入參數物件（33）。
- 圖卡指令：「把一段有獨立用途的邏輯抽成函式。」

### 27 重新命名變數
- 目的：讓名稱反映變數的用途
- 做法與注意：以它「代表什麼」命名，不以型別或暫時用途命名；作用範圍越大，名稱越要完整。改名要同步所有引用與相關註解，用 IDE 的 rename 或全專案搜尋，別手改漏。
- 圖卡指令：「把變數改成一看就知道它存什麼的名稱。」

### 28 修改函式宣告
- 目的：讓名稱和參數符合函式用途
- 做法與注意：改名稱、增減或重排參數。公開 API 用小步做法：先加新簽名、遷移呼叫端、最後移除舊的。
- 圖卡指令：「檢查並調整函式名稱和參數。」

### 29 抽取變數
- 目的：用名稱說明複雜運算的含義
- 做法與注意：把運算式的某一段指派給有名字的變數，名字就是註解。若同一個概念在函式外也用得到，改抽成函式（26）。
- 圖卡指令：「把長運算式抽成有明確名稱的變數。」

### 30 抽取類別
- 目的：拆開混在一起的職責
- 做法與注意：找出一群總是一起使用的欄位與方法，搬到新類別，原類別持有它。逐欄位、逐方法搬，不要一次搬完。
- 圖卡指令：「把同時負責兩件事的類別拆成兩個類別。」

### 31 內聯函式
- 目的：將多餘的函式包裝展開
- 做法與注意：函式本體和名稱一樣好懂，或只是單純轉呼叫時，把本體貼回呼叫端並刪掉函式。判準是「名稱是否比本體更好懂」。被多型覆寫或被外部引用的函式不能內聯。
- 圖卡指令：「如果函式本體和名稱一樣好懂，就把它內聯到呼叫端。」

### 32 拆分變數
- 目的：每個變數只負責一種用途
- 做法與注意：同一個變數被賦值兩次以上且代表不同概念（`temp` 先存周長、後存面積），就各給一個名字。迴圈變數與累加器除外。
- 圖卡指令：「把同時用於兩種用途的變數拆開。」

### 33 引入參數物件
- 目的：把一組相關參數包成物件
- 做法與注意：把總是一起出現的參數包成物件或 type，簽名變短，也順便替這組資料找到歸屬，後續常會發現有行為可以搬進去。
- 圖卡指令：「把起始日和結束日包成一個參數物件。」

之前：

```ts
function amountInvoiced(startDate: Date, endDate: Date): number
```

之後：

```ts
/** 日期區間 */
type DateRange = {
  start: Date;
  end: Date;
};

function amountInvoiced(range: DateRange): number
```

### 34 移除旗標參數
- 目的：讓兩種操作各有清楚的名稱
- 做法與注意：用布林值或模式字串決定走哪條路的函式，拆成各自有名的函式。若只是把旗標原封轉傳，直接在呼叫端拆開。
- 圖卡指令：「把使用布林旗標切換行為的函式拆成兩個。」

之前：

```ts
function bookConcert(customer: Customer, isPremium: boolean): void
```

之後：

```ts
function bookRegularConcert(customer: Customer): void
function bookPremiumConcert(customer: Customer): void
```

### 35 分離查詢與更新
- 目的：將回傳資料與改變狀態的操作分開
- 做法與注意：查詢函式不該有副作用，命令函式不回傳業務資料，拆成 `getX` 與 `updateX`。需要原子性（取號並遞增）或慣用語法（`stack.pop()`）時可以例外，並寫下原因。
- 圖卡指令：「把同時回傳值又修改狀態的函式拆成兩個。」

### 36 移動函式
- 目的：讓函式靠近它主要操作的資料
- 做法與注意：函式使用另一個模組或類別的資料多於所在位置，就搬到資料所在處。搬之前確認它依賴的東西跟得上；呼叫端還沒全部遷移前，原處先保留轉呼叫。
- 圖卡指令：「把函式移到它最常使用的資料所在的位置。」

### 37 拆分處理階段
- 目的：依處理順序拆成獨立階段
- 做法與注意：一段程式同時處理 A 再 B 兩個階段（先解析輸入、再計算），用中間資料結構隔開，各自成為一個函式。
- 圖卡指令：「把讀取與計算拆成兩個處理階段。」

### 38 將函式整合到類別
- 目的：集中呼叫同一份資料的函式
- 做法與注意：多個函式圍繞同一份資料轉來轉去，就讓它們成為同一個類別（或模組）的方法，資料成為它的狀態。不用 class 的程式碼，可用模組內聚或閉包達到同樣效果。
- 圖卡指令：「把處理同一份資料的函式整合到一個類別。」

### 39 內聯變數
- 目的：去掉沒有額外意義的中間變數
- 做法與注意：變數名稱沒比運算式更好懂、又只用一次，就換回運算式。運算式有副作用，或昂貴且被多次使用時，不要內聯。
- 圖卡指令：「把沒有額外意義的變數換回原運算式。」

### 40 替換演算法
- 目的：以更簡單的方式得到相同結果
- 做法與注意：用更簡單、等價的做法取代複雜的演算法。前提是有測試能證明結果相同（特徵測試 76、黃金樣本 99）；一次只換一個，不順手改行為。
- 圖卡指令：「用更簡單、結果相同的演算法替換現有做法。」

### 41 移動陳述式
- 目的：把相關的程式碼移到一起
- 做法與注意：讓同一件事相關的宣告與使用相鄰（變數宣告貼近第一次使用），為之後抽取函式鋪路。不要跨越有副作用或順序相依的陳述式。
- 圖卡指令：「調整陳述式的順序，讓相關的程式碼相鄰。」

### 42 函式參數化
- 目的：把只有固定值不同的函式合併
- 做法與注意：兩個函式邏輯相同、只差字面值，就合併成一個並把差異當參數。若差異是行為而不只是值，改用策略（61）。
- 圖卡指令：「把只差數值的函式合併，用參數傳入差異。」

### 43 隱藏委派
- 目的：讓呼叫端透過外介面操作
- 做法與注意：呼叫端用 `a.getB().doX()` 穿透取得內部元件再操作，就在 `a` 上加 `a.doX()` 轉發，呼叫端不必認識 B。別因此長出一堆只會轉發的方法（19 中間人）。
- 圖卡指令：「讓呼叫端透過中介物件存取，封裝內部元件。」

### 44 移除中間人
- 目的：去掉只負責轉傳的中介層
- 做法與注意：與 43 相反。當一個類別的方法大半只是轉發，讓呼叫端直接找被委派的物件。43 與 44 之間找平衡，看轉發方法有沒有承載封裝的價值。
- 圖卡指令：「移除只負責轉呼叫的中介方法。」

### 45 內聯類別
- 目的：把職責過少的類別併回使用端
- 做法與注意：與 30 相反。類別職責萎縮到幾乎沒事做，就把成員併回使用它的類別並刪除原類別。
- 圖卡指令：「把幾乎空白的類別併入使用它的類別。」

### 46 工廠函式
- 目的：集中物件的建立邏輯
- 做法與注意：建立物件需要選擇型別、組合設定或處理預設值時，集中到一個 `createX`，呼叫端不再各自 new。建構子很單純、沒有選擇邏輯就不需要。
- 圖卡指令：「把建立物件的邏輯集中到工廠函式。」

### 47 封裝變數
- 目的：集中變數的讀寫方式
- 做法與注意：可被各處直接改寫的資料，改成只能透過 getter、setter 或函式存取，之後才能集中加驗證、記錄與變更通知。搬動共用資料前的第一步；不可變常數不必封裝。
- 圖卡指令：「讓共用變數只能透過函式讀寫。」

### 48 上移方法
- 目的：把子類別重複的方法移到父類別
- 做法與注意：多個子類別有完全相同的方法時移到父類別。只是「相似」的話，先讓它們變成完全相同（例如用 42），再上移。
- 圖卡指令：「把子類別中重複的方法上移到父類別。」

### 49 抽取父類別
- 目的：把相似類別的共同行為抽出來
- 做法與注意：兩個類別有相似的欄位或行為，建立共同父類別，並逐步上移共同部分（先欄位、再方法）。同時想想用委派是否比繼承更合適。
- 圖卡指令：「把兩個相似類別的共同部分抽到父類別。」

### 50 攤平類別階層
- 目的：合併沒有差異的父子類別
- 做法與注意：與 49 相反。父類別與子類別沒有實質差異時合併成一個類別。
- 圖卡指令：「把沒有實質差異的父類別和子類別合併。」
