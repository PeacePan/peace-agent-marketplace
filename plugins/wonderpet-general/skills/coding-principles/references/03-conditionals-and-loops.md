# 條件分支與迴圈（51–75）

目的：整理 if、迴圈和錯誤處理。

這一組的共同目標是讓控制流程「一路讀下去不用回頭」。幾個招式有適用門檻（多型、策略、狀態模式、狀態機），分支少而且穩定時，一般的 if 或 switch 反而最清楚；用之前先看 SKILL.md 的「取捨」一節。

每則的「圖卡指令」是原圖卡上給 AI 的標準說法；「做法與注意」是補充說明，不是圖卡原文。範例以 TypeScript 為主，其他語言請以對應的語法類推。

---

### 51 守衛子句
- 目的：先處理例外情況並提早返回
- 做法與注意：把「例外或不適用」的情況放在函式開頭先 return（或 throw、continue），主流程留在最外層縮排。兩個分支權重相當時（對稱判斷）才保留 if/else。
- 圖卡指令：「用守衛子句改寫巢狀 if，先用 return 處理例外情況。」

之前：

```ts
function getPayAmount(employee: Employee): number {
  let result: number;
  if (employee.isSeparated) {
    result = separatedAmount();
  } else {
    if (employee.isRetired) {
      result = retiredAmount();
    } else {
      result = normalAmount();
    }
  }
  return result;
}
```

之後：

```ts
function getPayAmount(employee: Employee): number {
  if (employee.isSeparated) return separatedAmount();
  if (employee.isRetired) return retiredAmount();
  return normalAmount();
}
```

### 52 拆解條件式
- 目的：用名稱說明複雜條件
- 做法與注意：把含 `&&`、`||` 的複雜條件與各分支抽成有名字的函式（如 `isSummer(date)`），讓判斷讀起來像一句話。
- 圖卡指令：「把複雜的條件式抽成有名稱的函式。」

### 53 合併條件式
- 目的：集中會導向同一結果的條件
- 做法與注意：連續幾個判斷導向相同結果，就用 `||` 合併並替合併後的條件命名。若各判斷其實是互不相關的獨立檢查，不要合併。
- 圖卡指令：「把結果相同的多個 if 合併為一個條件式。」

### 54 多型
- 目的：讓各型別自行實作對應行為
- 做法與注意：依型別或種類而行為不同的 switch，改成各型別各自實作同名方法，呼叫端只管呼叫。前提是這個 switch 重複出現（16）或預期分支會增長；單處且穩定的 switch 保留即可。TypeScript 可用判別聯合型別（discriminated union）加窮盡檢查取代 class 繼承。
- 圖卡指令：「用多型取代依型別判斷的 switch。」

### 55 拆分迴圈
- 目的：讓每個迴圈專心做一件事
- 做法與注意：一個迴圈同時算兩件事（既累加總和、又找最大值），就拆成兩個迴圈，之後各自可抽成函式或改成管線（59）。多跑一次迴圈通常不是瓶頸，熱路徑先量測再決定。
- 圖卡指令：「把同時做兩件事的迴圈拆成兩個。」

### 56 引入特殊案例
- 目的：集中重複出現的特殊情況處理
- 做法與注意：多處檢查 null 或「未知客戶」並套用相同的預設行為，就建立特殊案例物件（Null Object，例如 `UnknownCustomer`），具備相同介面與預設行為，呼叫端就不必判斷。
- 圖卡指令：「把重複的空值判斷集中到特殊案例的實作。」

### 57 引入斷言
- 目的：在程式碼中明確寫出前置條件
- 做法與注意：用斷言宣告「此處一定成立」，把隱含假設寫成可執行的文件。斷言標示的是「不應發生的程式錯誤」，使用者輸入錯誤要走驗證（62），不是斷言。
- 圖卡指令：「用斷言明確寫出執行前必須成立的條件。」

### 58 移除控制旗標
- 目的：用明確的控制流程結束迴圈
- 做法與注意：用旗標變數（`done`、`found`）控制迴圈或後續流程，改用 break、continue 或 return。抽成函式後常可直接 return。
- 圖卡指令：「把控制迴圈的旗標改成 break 或 return。」

### 59 集合處理管線
- 目的：將迴圈改成連續的集合操作
- 做法與注意：用 for 迴圈做過濾、轉換、累加，改成 filter、map、reduce 串成的管線，每一階段保持簡單。有副作用的迴圈（I/O、需要提早結束）不要硬轉；大型陣列要留意中間陣列的成本。
- 圖卡指令：「把 for 迴圈改寫成由 filter 和 map 組成的處理管線。」

### 60 查找表
- 目的：用對照表取代一長串條件分支
- 做法與注意：長 if/else-if 或 switch 只是把 key 對應到結果時，改成 Map 或物件。分支裡有複雜邏輯、不是單純對映時不適用。
- 圖卡指令：「把冗長的 if / else if 改成查找表。」

之前：

```ts
function getGradeLabel(grade: string): string {
  if (grade === 'A') return '優良';
  if (grade === 'B') return '良好';
  if (grade === 'C') return '待加強';
  return '未知';
}
```

之後：

```ts
const gradeLabels: Record<string, string> = {
  A: '優良',
  B: '良好',
  C: '待加強',
};

function getGradeLabel(grade: string): string {
  return gradeLabels[grade] ?? '未知';
}
```

### 61 策略模式
- 目的：讓不同的計算方式可以替換
- 做法與注意：把「選擇演算法的分支」改成可替換的策略，由呼叫端或設定注入。TypeScript 與 JavaScript 中，傳入一個函式往往就夠了，不必建立類別階層。
- 圖卡指令：「把選擇計算方式的分支改成策略模式。」

### 62 快速失敗
- 目的：發現不合法的值就立即停止
- 做法與注意：在系統邊界（API 請求、外部輸入、設定載入）立刻驗證並丟出明確的錯誤，不讓壞資料流進深處。只在邊界驗證；內部已被型別保證的值不重複防禦。
- 圖卡指令：「一開始就驗證輸入，有錯就立即回報並停止。」

### 63 三元運算子
- 目的：用一個運算式表達簡單分支
- 做法與注意：僅用於「依條件挑選一個值」的簡短單層賦值。巢狀三元、含副作用、或兩邊很長時，保留 if/else 或改用守衛子句（51）。
- 圖卡指令：「把只用來決定指派值的簡短 if 改成三元運算子。」

### 64 德摩根定律
- 目的：簡化含有否定的複合條件
- 做法與注意：`!(A && B)` 等於 `!A || !B`，`!(A || B)` 等於 `!A && !B`，用來消去外層否定，讓條件以正面說法表達。改完用真值表或測試確認等價。
- 圖卡指令：「用德摩根定律整理多重否定的條件式。」

### 65 可選鏈結
- 目的：簡化逐層檢查 null 的巢狀判斷
- 做法與注意：用 `a?.b?.c` 取代逐層 `&&`。可選鏈結只處理 null 與 undefined，不處理 `0`、`''`、`false`。別連鎖過長，掩蓋「本來就不該為空」的錯誤，那種情況用快速失敗（62）。
- 圖卡指令：「把逐層檢查 null 的巢狀判斷改成可選鏈結。」

### 66 空值合併運算子
- 目的：簡潔地指定空值時的預設值
- 做法與注意：用 `x ?? fallback` 指定預設值，只在 null 或 undefined 時生效；和 `||` 的差別在於 `0`、`''`、`false` 不會被蓋掉。預設值賦值優先用 `??`。
- 圖卡指令：「用空值合併運算子 ?? 指定預設值。」

### 67 列舉型別
- 目的：避免狀態字串拼錯
- 做法與注意：用 enum 或字串聯集型別（`'OPEN' | 'CLOSED'`，或 `as const` 物件）取代散落各處的狀態字串，讓拼錯變成編譯錯誤。
- 圖卡指令：「把代表狀態的字串改成列舉型別。」

### 68 狀態模式
- 目的：將各狀態的行為拆開
- 做法與注意：物件行為隨狀態差很多，而且 `if` 或 `switch (state)` 到處都是，就每個狀態一個類別或物件，各自實作該狀態下的行為與轉移。狀態少、行為簡單時，列舉加查找表就夠了。
- 圖卡指令：「用狀態模式整理依狀態切換的行為。」

### 69 模式比對
- 目的：讓依型別判斷的分支更易閱讀
- 做法與注意：依型別或結構分流時，用語言內建的模式比對（Python 的 match、Rust 與 Kotlin 的 match、when、C# 的 switch 運算式）。TypeScript 沒有原生模式比對，用判別聯合加 switch 與窮盡檢查達到類似效果。
- 圖卡指令：「用模式比對改寫依型別分流的邏輯。」

### 70 短路求值
- 目的：結果確定時跳過後續判斷
- 做法與注意：把便宜、最可能決定結果的條件放前面，昂貴的或依賴前者成立的判斷（`user && user.isActive`、先檢查長度再讀取）放後面。別把有副作用的呼叫藏在可能被短路跳過的位置。
- 圖卡指令：「把成本較低的條件放前面，利用短路求值。」

### 71 吞掉例外
- 目的：留下錯誤資訊，避免問題被忽略
- 做法與注意：找出 catch 裡空白、或只 return null 與預設值卻沒留下任何紀錄的地方，至少記錄（原因加脈絡），或重新拋出，或回傳明確的失敗結果。只有「預期內且已知可忽略」的例外可以不處理，並註明原因。
- 圖卡指令：「找出吞掉例外的地方，將例外資訊寫入日誌。」

### 72 移出迴圈不變式
- 目的：把結果固定的運算移到迴圈外
- 做法與注意：每輪結果都相同的運算（取長度、建立正規表達式、查表、固定計算）移到迴圈外。先確認它真的不依賴迴圈內的狀態，且迴圈內不會改變它的輸入。
- 圖卡指令：「把每輪結果都相同的運算移到迴圈外。」

### 73 狀態機
- 目的：明確定義各狀態如何轉換
- 做法與注意：多個布林旗標組合出隱含狀態（`isLoading && !hasError && …`）時，明確列出狀態與合法轉移，消除非法組合。TypeScript 可用判別聯合加 reducer。
- 圖卡指令：「用狀態機整理多個旗標的組合與轉換。」

### 74 決策表
- 目的：用表格檢查條件組合有沒有漏掉
- 做法與注意：多個條件組合決定結果時，先用表格列出所有組合與預期結果，找出遺漏與矛盾，再用查找表或條件式實作，每一列至少對應一個測試。
- 圖卡指令：「用決策表逐一檢查條件組合與對應結果。」

### 75 尤達寫法
- 目的：降低比較式誤寫成指派的機會
- 做法與注意：比較時把常數放左邊（`0 == x`），誤寫成 `=` 會直接編譯失敗。在 JS 與 TS 用嚴格比較再加 lint（`no-cond-assign`）已能攔截，且這種寫法讀起來較不自然，除非專案規範要求，否則預設不採用。
- 圖卡指令：「把比較式統一成常數放左邊的尤達寫法。」
